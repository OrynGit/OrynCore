# HTTP/2 传输（`network: h2`）

V2Ray 的 HTTP/2 传输，参照 sing-box `transport/v2rayhttp`（1.12.8 / 1.13.14）核对行为，未移植其代码。Trojan / VLESS / VMess 可用。

- 每个 Flow 一个 h2 流：`PUT https://{host}{path}`，请求体与响应体都是原始字节，没有 gRPC 的分帧。协议首部是请求体的第一段数据，不等响应就写出（服务端通常收到首部才回响应）。
- 与 gRPC 共用 `oryn-transport/src/h2pool.rs` 的连接池和上限：每出站最多 4 条 TLS h2 连接、每条最多 32 个流、每出站并发 128 个 Flow，细节见 [grpc.md](grpc.md)。
- 配置：`h2-opts.host`（列表，最多 8 项）、`h2-opts.path`（默认 `/`，必须以 `/` 开头、不含空白、`#`，最长 1024 字节）。`host` 取列表里的第一项作 `:authority`，没有配置时用服务器地址。V2Ray 是在候选里随机选一项；Oryn 取第一项，行为确定。
- 必须启用 TLS，ALPN 缺省自动用 `h2`；显式写了 `alpn` 时每一项都必须是 `h2`。没有 TLS 的 h2c 不支持。以上任何一条不满足都是整份配置失败，App 本地编辑器的校验规则相同。

## 测试

独立对端是 sing-box 的 `http` 传输入站（TLS，`alpn: [h2]`，`method: PUT`）：Trojan / VLESS / VMess 的 70000 字节 TCP 往返、UDP 往返、40 条并发 Flow 共享连接，path 写错时服务端 404、连接失败；在 sing-box 1.12.8 与 1.13.14 上通过。p2_engine 的 `h2` 例走真实 Engine，64 条并发 Flow 的 RSS 增量 0.11 MiB（[measurements/p2-rss-0.7.0.tsv](../../../docs/oryncore/measurements/p2-rss-0.7.0.tsv)）。
